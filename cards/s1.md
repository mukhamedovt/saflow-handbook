# Взаимодействие систем

Источник для чтения: [часть 1](https://habr.com/ru/articles/841646/). Здесь только то, что меняет постановку задачи.

Клиент начинает обмен, сервер отвечает. У запроса есть адрес, метод, заголовки и тело. Методы, которые аналитик называет явно: GET читает, POST создаёт, PUT заменяет целиком, PATCH меняет часть, DELETE удаляет. Длинный фильтр не кладут в адрес: у строки адреса есть предел, сложный отбор уходит в тело.

Тело чаще всего JSON: объект из пар «ключ — значение». Дата в контракте — строка с часовым поясом, не «дата как получится».

API — это контракт: операция, вход, выход, ошибки. Сначала контракт, потом код, если интеграцию ждут другие команды. Сначала код, потом контракт, если модуль внутренний и потребителей контракта ещё нет. Выбор записывают, а не оставляют умолчанием.

Синхронный вызов ждёт ответ. Асинхронный не ждёт. Ответ «запрос принят» с последующей обработкой — это уже не синхронный результат, даже если первый ответ пришёл сразу.

## Спросить в задаче

- Кто клиент и кто владеет данными.
- Какой метод и какие поля обязательны.
- Какая ошибка видна вызывающему, если сосед не ответил.
- Вызов ждёт результат или только факт приёма.
