# Интеграции

Источник: [часть 4](https://habr.com/ru/articles/844950/). Аналитик описывает обмен, а не настраивает брокер.

Пять способов: файл, общая база, удалённый вызов, сообщение, API. Общая база связывает приложения сильнее всего. Файл не даёт ответа сразу. Вызов и API ждут контракт. Сообщение нужно, когда получатель не обязан ответить в том же вызове.

Для HTTP-контракта фиксируют метод, путь, тело, коды и идемпотентность. GET, PUT и DELETE повторяют без второго эффекта. POST без ключа идемпотентности при повторе может создать вторую запись.

Сообщение без потребителя не описывают. Для брокера в требованиях оставляют то, что меняет поведение: имя канала или очереди, кто пишет, кто читает, ключ, что делать с дублем, сколько хранить. Если этого не знают, в контракте стоит TODO, а не выдуманное число партиций.

В 1С внешний обмен — это HTTP-сервис, SOAP, файл или план обмена. Внутренний вызов между модулями одной конфигурации брокером не называют.

Проверка контракта тестом — работа QA. Аналитик готовит пример запроса и ожидаемый код из сценария, чтобы тест было с чем сравнить.

## Спросить в задаче

- Это файл, общая база, вызов, сообщение или API.
- Кто потребитель, если сообщение уходит без ответа.
- Что будет при второй доставке того же сообщения.
