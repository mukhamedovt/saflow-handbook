# 06. Sequence

Диаграмма нужна, чтобы разработчик увидел порядок вызовов, а не пересказ бизнес-процесса. Её пишут в PlantUML по той же причине, что и DBML: текст легко править.

## На столе

- Use case с расширениями, которые надо показать.
- Разметка зон из шага 05.
- Зафиксированный список участников с алиасами. Модель не добавляет и не убирает имена из этого списка.

## Спросить

- Какая зона выполняет шаг, если из сценария это не следует. Пока ответа нет, на диаграмме стоит участник `???`.
- После какой записи в хранилище уходит событие.

## Модели можно

Синхронный вызов рисовать стрелкой `->`, ответ `-->`, асинхронную публикацию `->>`. Подпись содержит операцию и ключевые данные: `GET /orders/{id}/items`, а не слово «запрос». Расширения показывать через `alt` / `else`.

## Модели нельзя

Подменять пропуск участника догадкой. Публиковать событие до фиксации изменения, не отметив это как замечание. Смешивать на одной диаграмме роли бизнеса и технические компоненты, если список участников уже технический.

## Принять

Диаграмма начинается с `@startuml` и заканчивается `@enduml`. Участники совпадают со списком. У расширений, которые меняют порядок вызовов, есть ветка. Открытые вопросы стоят после диаграммы.

Файл `06-sequence.puml`. Промпт: `python3 saflow.py prompt <фича> 06`
